## Critical Issues (must fix)

1. **Cabeçalho quebra em duas linhas entre ~900px e 1099px, faixa que inclui o breakpoint 1024px exigido pela rubrica** → Em `tia-clara/10-site/css/site.css`, a media query da linha 291 (`@media (min-width: 860px) { .tc-menu { flex-basis: auto; } ... }`) faz o menu deixar de ser hambúrguer e virar navegação horizontal completa a partir de 860px, mas a soma real de `.tc-marca` + `nav#tc-menu` (6 links) + `.tc-cabecalho__cta` só cabe numa linha só a partir de **1100px** (medi com um script Playwright variando a largura pixel a pixel: 1099px = header de 114px de altura/2 linhas; 1100px = 73px/1 linha). Como `.tc-cabecalho__linha` (linha 279) é `display:flex; flex-wrap:wrap; justify-content:space-between`, entre 900 e 1099px o botão "Agendar apresentação" simplesmente quebra para uma segunda linha, à esquerda, solto, sem alinhamento com nada — visualmente idêntico a um bug de e-mail HTML quebrado. Confirmei isso de quatro formas independentes: (a) screenshot de seção em `dobra-1024.png`; (b) screenshot isolado do header em 860/1000/1075/1080px (`/tmp/.../header-1000.png`, `header-1080.png`); (c) clique real no link "Perguntas" em 1024px (`/tmp/.../faq-1024.png`, header ainda quebrado); (d) zoom de página a 200% num viewport de 1440px, que reduz a largura efetiva para ~720px e reproduz o mesmo bug (`/tmp/.../zoom200-top.png`) — ou seja, um usuário com baixa visão que amplia a página em um monitor comum também vê isso. **Este bug já existia na iteração 001** (visível no próprio `dobra-1024.png` daquela rodada, mas não foi citado no feedback-001) — não é uma regressão desta rodada, é um problema real que passou despercebido duas vezes. Como corrigir: suba o breakpoint que desliga o hambúrguer para `min-width: 1100px` (ou o valor exato onde tudo cabe, testando com o container em `max-width:1264px`); ou, para não perder a navegação completa em telas de 900–1099px, reduza o `gap` entre os links (`.tc-menu__lista`) e/ou o `font-size`/`padding` do `.tc-cabecalho__cta` nessa faixa específica com uma media query intermediária; ou droppe a navegação completa e mantenha o hambúrguer até 1100px. Qualquer uma resolve — o ponto é testar explicitamente 900, 1000, 1024 e 1099px depois do fix, não só 860 e 1440.

## Minor Issues (nice to fix)

1. **Screenshots de seção da própria ferramenta (`secao-1440-05-protocolos.png`, e prováveis outras) mostram o header sticky sobrepondo o topo da seção** → isso é um artefato do método de captura de `gan-harness/tools/avaliar.js` (provavelmente `element.scrollIntoView({block:'start'})`, que não compensa `position: sticky`), **não um bug do site**: testei clicando nos 6 links de navegação de verdade em 1440px e em nenhum caso o `<h2>` da seção-alvo fica coberto pelo header (a folga é de ~50px em todos os casos, graças ao `padding-top` generoso das seções). Vale considerar ajustar a ferramenta de avaliação para rolar `headerHeight` a menos, só para não confundir avaliações futuras — mas não é algo para o gerador corrigir no site.
2. **Overlay `.tc-menu__veu` usa `rgb(30 59 51 / 0.45)`, um valor de opacidade que não é um token nomeado** (`css/site.css` linha 273) → é literalmente Pinho (`#1E3B33` = `rgb(30 59 51)`) com alfa diferente do `--tc-borda` (que usa 0.16), então não é uma cor nova, mas também não é uma variável declarada em `tokens.css`. Considerar adicionar um token semântico (`--tc-veu` ou similar) em vez de um valor literal, para manter o Gate D1 sem exceção nenhuma.
